# AhaFrame AI Content Production v1.0

Issue: #146  
Source of truth: `content/ai-content-production-v1.0.json`

## Production rule

The Knowledge Graph is the curriculum. Content production creates Experiences over canonical Concepts; it does not create a parallel course taxonomy.

Every planned Experience must reference existing Path IDs and Concept IDs. Production waves prioritize learner value, transfer and interactive judgment—not chapter count.

## Wave 1 — First value

Goal: prove the expanded AhaFrame proposition immediately across technical and outcome-oriented entry points.

- Token Playground — open foundation;
- AI Code Review Mission — controlled agentic coding;
- Broken RAG Pipeline — evidence/authority failure;
- $47,000 Retry — Agent reliability;
- Research Evidence Mission — claims, sources and synthesis;
- Data Analysis Verification Lab — reproducible calculations and uncertainty.

This wave supplies several credible `FREE_CHOICE` options rather than forcing every learner through the same first chapters.

## Wave 2 — Build systems

Goal: connect concepts into complete workflows and outcome builds.

- Structured Output Contract Lab;
- MCP Capability Boundary Mission;
- Long-running Agent Recovery Mission;
- Write a Book with AI Build;
- Build an AI Knowledge Base;
- AI Customer Support Build;
- Course / Knowledge Product Build.

## Wave 3 — Scale and production

Goal: move from isolated workflows to architecture, orchestration and operating systems.

- Multi-Agent Coordination Incident;
- Production Release Gate Build;
- Model Adaptation Decision Lab;
- Solo Business Operating System Build.

## Access classification

`OPEN`, `FREE_CHOICE` and `MEMBERSHIP` in this plan are content classifications only.

The production manifest intentionally does not contain user IDs, remaining unlock counts, subscription records, checkout state or the numeric free-unlock quota. Those are entitlement concerns handled separately by #149.

Billing remains disabled during #146.

## Quality bar

An Experience counts only if it changes what the learner can inspect, decide, simulate, verify or build. Generic prose, duplicated concepts, framework documentation clones and decorative quizzes do not count.

The CI contract requires:

- all 15 current v1 Paths have at least one production Experience;
- all Experience concept/path references resolve to the canonical inventory;
- every Experience belongs to exactly one production Wave;
- seeded/existing Experience IDs already exist in the canonical v1 seed graph;
- at least one Experience is fully open;
- several meaningful `FREE_CHOICE` options exist;
- membership-classified content has real depth;
- Billing activation stays false.

## Next execution

The Wave manifest is a bounded backlog. Individual Experience packs can now be implemented independently while the Knowledge Map and entitlement layers consume the same canonical IDs.
